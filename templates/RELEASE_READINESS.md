# Release Readiness Checklist

## Product and scope
- [ ] Release scope and known limitations are approved.
- [ ] Core user journeys meet acceptance criteria.
- [ ] Product copy, help content and release notes are accurate.

## Engineering and quality
- [ ] Release build is reproducible and tied to a source revision.
- [ ] Required automated and manual tests have passed.
- [ ] No unresolved release-blocking defects remain.
- [ ] Performance and accessibility have been evaluated against project requirements.
- [ ] Supported platforms, OS versions, browsers or devices have been tested.

## Security and privacy
- [ ] Security review and dependency checks are complete.
- [ ] Secrets and signing credentials are protected.
- [ ] Privacy disclosures match actual data collection and SDK behavior.
- [ ] Data backup, export, deletion and recovery behavior are verified where applicable.

## Distribution
- [ ] Install / upgrade / rollback or store submission paths are tested.
- [ ] Signing, notarization or store requirements are complete where applicable.
- [ ] Metadata, screenshots, URLs and support contacts are accurate.
- [ ] Staged rollout and incident ownership are documented.

## Operations
- [ ] Monitoring, logs and alerts are active.
- [ ] Backup and recovery procedures are verified.
- [ ] Support and incident runbooks are ready.
- [ ] Release owner and go/no-go approver are identified.
